# Harness

Setup and operating instructions for the PM agent: `PM-SETUP.md`.

- `config.sh`: machine-specific paths and timings. Every script sources it.
- `harness.yaml`: who the agents are and the PM's loop and merge rules.
- `state.json`: phases, owners, status, checkpoint results. Source of truth.
- `agents/<name>.json`: model, session id, phase, `standby` (true = the heartbeat leaves it alone).
- `runtime/<name>.json`: last heartbeat and rate-limit wait. Written by the heartbeat, not committed.
- `STATUS.md`: regenerated by the heartbeat. Read this first.
- `QUESTIONS.md`: the agents' questions for the user, each with the answer they are assuming.
- `bin/launch-agents.sh`: creates each agent's worktree and opens its cmux workspace.
- `bin/heartbeat.sh`: run on a timer by `bin/heartbeat-loop.sh` in the cmux workspace `heartbeat`.
- `bin/checkpoint.sh <phase>`: runs `phases/<phase>.sh` and records pass or fail.
- `phases/<n>.sh`: the executable definition of "phase n is done". Helpers in `phases/lib.sh`.
